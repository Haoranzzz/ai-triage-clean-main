# Realtime 实时语音对话模块

## 项目简介

这是一个基于 WebSocket 的实时语音对话系统，支持语音识别（ASR）、大语言模型对话（LLM）和文本转语音（TTS）的完整流程。用户可以通过麦克风与AI进行自然的语音对话，系统会实时处理语音输入并生成语音回复。

## 核心功能

- 🎤 **实时语音识别**：基于 OpenAI Whisper 的流式语音识别
- 🤖 **智能对话**：集成 GPT-4o-mini 进行自然语言对话
- 🔊 **语音合成**：使用 OpenAI TTS 生成自然语音回复
- 🌐 **WebSocket 通信**：低延迟的实时双向通信
- 🎯 **连续对话模式**：支持多轮连续语音对话
- 🔇 **音频控制**：支持静音、音量调节等功能

### 核心模块详解

#### 1. WebSocket 服务 (`ws.py`)

**主要功能：**
- 提供 WebSocket 端点 `/ws/talk`
- 处理客户端连接和消息路由
- 协调 ASR、LLM、TTS 三个模块的工作流程
- 管理音频数据的实时传输

**关键特性：**
- 支持二进制音频数据和 JSON 文本消息
- 异步处理多个并发连接
- 自动错误处理和连接状态管理
- 优化的音频批处理（150ms 批次）

#### 2. 语音识别模块 (`asr.py`)

**技术实现：**
- 使用 OpenAI Whisper API 进行语音转文字
- 支持流式处理，600ms 批次转写
- 集成语音活动检测（VAD）
- 智能句子完整性判断

**核心算法：**
```python
# 音频参数配置
SAMPLE_RATE = 16_000    # 16kHz 采样率
FRAME_MS = 20          # 20ms 音频帧
CHUNK_MS = 600         # 600ms 批次处理
```

**特色功能：**
- 自动静音检测和端点检测
- 音频能量计算和噪声基线校准
- 支持连续语音和间断语音处理
- 智能句子边界识别

#### 3. 大语言模型模块 (`llm.py`)

**模型配置：**
- 默认使用 GPT-4o-mini 模型
- 专门优化的医疗助手提示词
- 流式响应生成，降低延迟

**系统提示词：**
```
You are a concise English-speaking medical intake assistant. 
Ask targeted follow-ups in short sentences. Do not diagnose.
```

**功能特点：**
- 支持多轮对话历史管理
- 句子完整性智能判断
- 温度参数优化（0.3）确保回复稳定性

#### 4. 文本转语音模块 (`tts.py`)

**技术规格：**
- 使用 OpenAI TTS API
- 默认 "alloy" 语音
- WAV 格式输出，便于前端播放
- 流式音频生成，8KB 块大小

#### 5. 状态管理 (`state.py`)

**会话状态：**
```python
@dataclass
class SessionState:
    session_id: str              # 会话唯一标识
    audio_q: asyncio.Queue      # 音频数据队列
    running: bool               # 运行状态
    turn: int                   # 对话轮次
    history: List[Dict]         # 对话历史
```

#### 6. 前端界面 (`realtime_demo.html`)

**界面特性：**
- 现代化响应式设计
- 实时语音波形显示
- 聊天记录展示
- 音频播放控制
- 连接状态指示

**核心功能：**
- 自动连接服务器
- 实时音频录制和播放
- WebSocket 消息处理
- 连续对话模式支持

## 使用方法

### 1. 环境配置

确保 `.env` 文件包含必要的 API 密钥：

```bash
OPENAI_API_KEY=your_openai_api_key_here
OPENAI_CHAT_MODEL=gpt-4o-mini
OPENAI_ASR_MODEL=gpt-4o-mini-transcribe
```

### 2. 启动服务

```bash
# 在项目根目录运行
python run_realtime.py
```

### 3. 访问界面

打开浏览器访问：`http://localhost:8000`

### 4. 使用流程

1. **自动连接**：页面加载后自动连接 WebSocket 服务
2. **开始录音**：点击"开始录音"按钮或直接开始说话
3. **语音对话**：系统自动处理语音识别、对话生成和语音合成
4. **连续对话**：支持多轮连续对话，无需重复点击按钮

## API 接口

### WebSocket 消息格式

#### 客户端 → 服务端

```javascript
// 开始录音
{
  "type": "audio.start"
}

// 音频数据（二进制）
// 直接发送 PCM 音频数据

// 停止录音
{
  "type": "audio.stop"
}
```

#### 服务端 → 客户端

```javascript
// 服务器确认
{
  "type": "server.ack",
  "event": "audio.start"
}

// 部分识别结果
{
  "type": "server.partial",
  "text": "用户正在说的话..."
}

// 最终识别结果
{
  "type": "server.final",
  "text": "完整的用户输入",
  "turn": 1
}

// AI 回复文本
{
  "type": "server.token",
  "text": "AI回复的文字"
}

// TTS 音频开始
{
  "type": "server.say",
  "audio_seq": 1,
  "ended": false
}

// TTS 音频数据（二进制）
// 直接发送 WAV 音频数据

// TTS 音频结束
{
  "type": "server.say",
  "audio_seq": 1,
  "ended": true
}
```

## 性能优化

- 使用 16kHz 单声道音频减少数据量
- 150ms 批次处理平衡延迟和稳定性
- 智能静音检测减少无效处理

### 2. 网络传输优化

- 流式处理减少内存占用

### 3. 用户体验优化

- 自动连接减少用户操作
- 实时状态反馈
- 连续对话模式提升交互流畅性

## 故障排除

### 常见问题

1. **麦克风权限问题**
   - 确保浏览器已授予麦克风权限
   - 检查系统麦克风设置

2. **WebSocket 连接失败**
   - 确认服务器正在运行
   - 检查防火墙设置
   - 验证端口 8000 是否可用

3. **API 调用失败**
   - 验证 OpenAI API 密钥是否正确
   - 检查网络连接
   - 确认 API 配额是否充足

4. **音频播放问题**
   - 检查浏览器音频权限
   - 确认音量设置
   - 尝试刷新页面
